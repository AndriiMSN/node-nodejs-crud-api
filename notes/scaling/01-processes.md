# 01. Что такое процесс в ОС

## Процесс — это программа в работе

Когда ты запускаешь `node app.js`, операционная система создаёт **процесс** — изолированную единицу выполнения. Это не просто файл кода, это живая сущность с собственными ресурсами.

Каждый процесс получает от ОС:
- **PID (Process ID)** — уникальный числовой идентификатор
- **Собственную память** — другие процессы не могут к ней обратиться напрямую
- **Собственный стек вызовов** — история выполнения функций
- **Дескрипторы файлов** — открытые файлы, сокеты
- **Переменные окружения** — `process.env` в Node.js

```js
console.log(process.pid);     // 12345 — ID этого процесса
console.log(process.ppid);    // 12344 — ID родительского процесса
console.log(process.env.PORT); // переменные окружения
```

## Изоляция памяти — ключевое свойство

Представь два процесса A и B:

```
Процесс A                  Процесс B
┌──────────────┐           ┌──────────────┐
│ let x = 1    │           │ let x = 1    │
│ x = 99       │           │              │
│              │           │ console.log(x)│ → 1, а не 99
└──────────────┘           └──────────────┘
```

Если процесс A меняет свою переменную `x`, процесс B **ничего не узнаёт об этом**. У каждого своя копия памяти.

Это одновременно:
- **Преимущество** — изоляция. Если процесс A упадёт с ошибкой, процесс B продолжит работу
- **Сложность** — нужно специальные механизмы (IPC) чтобы процессы могли общаться

## Зачем запускать несколько процессов?

### Причина 1: Node.js однопоточный

Node.js выполняет JavaScript в **одном потоке**. Это значит, что в один момент времени выполняется только одна операция. Если у тебя 8-ядерный процессор — 7 ядер простаивают.

```
Один процесс Node.js:

CPU 0 ████░░░░░░  ← только это ядро работает
CPU 1 ░░░░░░░░░░  ← простаивает
CPU 2 ░░░░░░░░░░  ← простаивает
CPU 3 ░░░░░░░░░░  ← простаивает
```

Несколько процессов:

```
CPU 0 ██████████  ← Worker 1
CPU 1 ██████████  ← Worker 2
CPU 2 ██████████  ← Worker 3
CPU 3 ██████████  ← Worker 4 (Load Balancer)
```

### Причина 2: Изоляция ошибок

Если Worker 1 упал из-за необработанного исключения — Workers 2 и 3 продолжают обрабатывать запросы. Пользователи не заметят.

### Причина 3: Параллелизм CPU-интенсивных задач

Если нужно обработать 1000 изображений — можно разделить работу между процессами. Каждый возьмёт по 250 изображений.

## Дерево процессов

Процессы имеют иерархию — каждый создаётся кем-то:

```
bash (PID: 100)
└── node cluster.ts (PID: 200)  ← Primary
    ├── node cluster.ts (PID: 201)  ← Worker 1
    ├── node cluster.ts (PID: 202)  ← Worker 2
    └── node cluster.ts (PID: 203)  ← Worker 3
```

Процесс, который создал другой — **родитель (parent)**. Созданный — **дочерний (child)**. В Node.js это `process.ppid` (parent PID).

---

## Жизненный цикл процесса

```
Создание → Выполнение → Завершение
  fork()   →   работа  →  exit(0)
```

Процесс завершается когда:
- Исполнение дошло до конца файла
- Вызван `process.exit(код)`
- Пришёл сигнал от ОС (например, `SIGTERM`)
- Произошла необработанная ошибка

Код завершения: `0` — успех, любое другое число — ошибка.
